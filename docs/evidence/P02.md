## The committed fixture

`test/fixtures/db/P02.sql` is the populated M2 database P03+ migrate forward from. `test/integration/db/migrate-forward.test.ts` restores it into an empty database and asserts:

- `migrate()` applies **zero** files — the dump already carries every M2 migration;
- every payment satisfies the aggregate rules when the deferred constraints are set immediate;
- every outbox row still carries its hot envelope, so nothing was lost in the round trip.

It contains **no terminal operations** (risk R8): P06 adds an evidence foreign key to operations, and a
terminal operation would need evidence rows this fixture cannot invent before P06 exists.

## Open item — the Docker Compose walkthrough

`pnpm db:up` succeeds (Postgres, Pub/Sub emulator, Jaeger healthy). The documented sequence
`migrate --bootstrap` → `migrate` → `seed --profile dev` then fails at the seed with
`relation "identity.merchants" does not exist`, which means the migrations are not reaching the Compose
database even though `migrate` exits 0. The integration lane covers all of this through Testcontainers, so
the M2 guarantees above are verified; what is unverified is the _Compose_ wiring specifically.

Not resolved here because P02-GATE may not modify `apps/**` or `packages/database/**` — a fix would be a
feature change, which this commit is forbidden to make. Raised as a follow-up: `db:migrate` and `db:seed`
scripts do not exist in `package.json`, and the CLI needs `DATABASE_ADMIN_URL` to bootstrap. Likely cause
is the CLI resolving a different database name than the one Compose creates, or `migrate` reporting
success while applying nothing because the migrations directory resolves differently from `apps/cli`.
